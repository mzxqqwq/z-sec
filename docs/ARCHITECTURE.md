# DASCTF 自动打靶系统 —— 架构说明（团队版 v1）

> 目标赛事：第九届西湖论剑「AI Agent 解题夺旗」（game.gcsis.cn，仅开放 API）
> 系统代号：ctf-agent | 代码根：D:\ctf-agent | 更新时间：2026-08-15

---

## 1. 一句话定位

**一套"人定战略、AI 打执行"的 CTF 自动解题流水线**：从比赛平台 API 自动拉题，
派发多个 AI 解题员（pi agent）在装满安全工具的 Kali Linux 上并行解题，
自动提取并提交 flag；人通过"提示注入"接口随时纠正方向。

比赛的本质要求（官方原话）："谁能将人的安全基础能力沉淀为 AI Agent 的系统能力"。

---

## 2. 总体架构

```
┌─────────────────────────────────────────────────────────────────────┐
│                        👤 人（总指挥）                               │
│   定目标 / 调优先级 / 写提示(hints) / 盯盘     ← DSH 网页作为驾驶舱    │
└──────────────────────────┬──────────────────────────────────────────┘
                           │ 写文件即生效（hints/<题号>.md）
┌──────────────────────────▼──────────────────────────────────────────┐
│  ① 编排器 orchestrator（Python，自研 ~300 行）      【指挥官】        │
│   黑板 state.json：每题一行状态(Fact) + 尝试记录                       │
│   循环：拉题 → 对未解题派 worker → 抽 flag → 提交 → 记录              │
└──────┬──────────────────────────────┬───────────────────────────────┘
       │ 派发提示词（题目JSON+附件路径+人工提示）   ▲ 交回 flag
┌──────▼──────────────────────────────┴───────────────────────────────┐
│  ② 解题员 worker = pi（earendil-works/pi，MIT 开源）  【解题员】      │
│    每道题一个独立进程，可并行多个；也可同题多模型竞速（后续）          │
│    大脑 = DeepSeek（v4-pro 主 / v4-flash 快），可换任何 OpenAI 兼容模型│
│    知识 = SKILL.md 技能包（每类题型一套方法论，按需加载）             │
│    循环：思考 → 调工具(read/write/edit/bash) → 看结果 → 再思考       │
└──────┬──────────────────────────────────────────────────────────────┘
       │ read/write/edit/bash 经「Kali 桥」转发
┌──────▼──────────────────────────────────────────────────────────────┐
│  ③ 执行环境 Kali Linux（10.174.153.128）          【工具箱】          │
│    pwntools / angr / z3 / sympy / gdb(待装) / nmap / sqlmap /        │
│    binwalk / john / hashcat / radare2 / zsteg …（root 权限）         │
│    ← 由 pi 扩展 kali.ts 通过 REST API（:5000/api/command）调用       │
└──────┬──────────────────────────────────────────────────────────────┘
       │ HTTP
┌──────▼──────────────────────────────────────────────────────────────┐
│  ④ 比赛平台 DASCTF（外部，不可控）                 【考场】           │
│    /api/challenges 拉题 · /submit 交 flag · /scoreboard 查分         │
│    ← 由平台客户端 dasctf_client.py 访问（cookie 会话 + 限频纪律）    │
└─────────────────────────────────────────────────────────────────────┘
```

**物理分布**：编排器、pi worker、平台客户端跑在 Windows 本机；解题动作（跑工具、
写 exp、连靶机）全部落在 Kali 上。Windows 只出"脑子"，Kali 出"手"。

## 3. 一次解题的完整数据流（以 misc 题为例）

1. 编排器轮询平台 API，发现新题 → 写入黑板（status=open）
2. 下载附件到 `workspace/challenges/<题号>/attachments/`
3. 渲染提示词 = 题目 JSON + 附件说明 + 人工提示（若有）→ 启动一个 pi 进程
4. pi 读题 → 决定用 bash 跑 `file`/`binwalk`/`strings` → 这些命令经 kali.ts
   变成 REST 请求发给 Kali → Kali 执行返回结果
5. pi 从输出里找到 `DASCTF{...}` → 用约定格式 `FLAG: xxx` 输出最终答案
6. 编排器从 pi 输出里用正则抽取 flag → 调平台 /submit（限次+冷却防封）
7. 成功 → 黑板标记 solved；失败 → 记录尝试，人工可写 hints 再派一轮

## 4. 为什么这么设计（对齐冠军方案的选择）

| 设计选择 | 依据 |
|---|---|
| 解题员用现成 agent 运行时 pi，不自己写 agent 循环 | pi 是腾讯黑客松唯一 AK 战队 Cairn 官方支持的 worker 后端之一；自写循环 3 天写不完且质量低 |
| 黑板 + Fact/Intent/Hint 三原语 | 抄 Cairn（唯一 AK 的架构）：无角色分工、无复杂多 agent 通信，人可随时注入意图 |
| 执行后端可替换（Kali 桥） | 抄 pi 的 FileSystem/Shell 抽象 + 官方 ssh.ts 示例模式：换靶场环境不改 agent 逻辑 |
| 模型可替换（OpenAI 兼容） | 比赛可能限制模型或给百炼额度；DeepSeek/百炼/GLM 随时切换，穷题用便宜模型 |
| 题型知识用 SKILL.md | 每类题型（web/pwn/re/crypto/misc）一份方法论，按题面让模型自选加载，不堆通识 RAG（Cairn 教训：通识 RAG 锁死上限） |
| 交卷纪律（限次/冷却/flag 正则） | 抄 Koshary/verialabs：错误提交会被平台惩罚，这是"脏活决定名次"的部分 |

## 5. 团队可优化/改进的点（当前版本的"旋钮"）

| # | 优化点 | 现状 → 目标 |
|---|---|---|
| 1 | **模型路由** | 现在全题 deepseek-v4-pro → 按题型分模型（pwn/web 用强推理，misc 用 flash）+ 同题多模型竞速 |
| 2 | **技能包内容** | 目前空 → 把团队积累的每类题型 checklist/工具链写成 SKILL.md |
| 3 | **Kali 工具链** | 缺 gdb（源冲突待修）、SageMath → 补齐 |
| 4 | **交互式工具** | Kali 桥是"一次性命令" → 加 SSH pty 通道支持 gdb/nc 交互（EnIGMA 结论：pwn/web 胜负手） |
| 5 | **并行度** | 现在每轮串行派 worker → 多题并行 + 每题 2-3 个不同模型 worker 竞速 |
| 6 | **成本熔断** | 无 → 单题 token/费用上限，超限降级 flash 或放弃 |
| 7 | **提示词模板** | 一份通用模板 → 按题型/阶段的模板库（recon/exploit/flag 提取分阶段提示） |
| 8 | **复盘沉淀** | 尝试记录只存文本 → 自动把成功经验沉淀成 SKILL.md/知识库 |
| 9 | **平台适配** | 端点是猜的 → 8/18 测试赛抓真实 API 后集中改 dasctf_client.py 的 EP 类 |
| 10 | **人机交互** | 写 hints 文件 → 网页看板（题目状态/花费/提交记录可视化） |
