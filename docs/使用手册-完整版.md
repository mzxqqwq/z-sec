## 一、系统全景与模型架构

```
┌─ Windows ────────────────────────────────────────────────────────────┐
│ ctf_orchestrator.py（指挥官，单进程）                                  │
│   60s 拉题 → Planner(强模型出总体思路) → 每题 1强+1弱 worker 竞速       │
│   → Supervisor 旁路监督(6轮审查, 维护看板, 纠偏提醒)                    │
│   → ralph-loop 续跑(agent_end 未解自动继续)                            │
│   → deadline-90s conclude 收尾 → 提交(经 worker-api 统一)              │
│ pi worker（node cli.js --mode rpc，每题 2 个进程）                     │
│   kali.ts 扩展：bash/读写文件→SSH→Kali；submit_flag/get_hint→worker-api│
│                  check_findings→message bus；kb_search→KB 服务          │
│   loop-detect.ts 扩展：循环软警告/阻止                                 │
│ dashboard.py（Flask :8088）：状态/摘要/hint/复核 API + React UI 静态页   │
│ kb_server.py（:8099，只读检索，可选）                                   │
└───────────────────────────────────────────────────────────────────────┘
         │ SSH (root，secrets/kali.json)
         ▼
┌─ Kali（10.174.153.128，NAT）──────────────────────────────────────────┐
│ /root/ctf/<cid>/w<idx>/   每 worker 独立工作目录（attachments/）       │
│ 工具链：pwntools/angr/z3/sympy/fpylll/blutter/stegseek/jadx/...        │
│ REST :5000 /health 保留作健康闸门（工具调用已走 SSH）                    │
└───────────────────────────────────────────────────────────────────────┘
```

## 四、操作指南

### 4.1 跑 benchmark（评测模式，无 UI）

```powershell
cd D:\ctf-agent

# CTFTiny 50 题（默认）
python src/ctf_orchestrator/eval_run.py --platform ctftiny --config src/ctf_orchestrator/l2-config.json

# NYU 全量 257 题
python src/ctf_orchestrator/eval_run.py --platform ctftiny --bench-root D:/ctf-agent/benchmarks/nyu-ctf-bench --bench-meta test_dataset.json --config src/ctf_orchestrator/l2-config.json

# Cybench 静态 19 题
python src/ctf_orchestrator/eval_run.py --platform cybench --config src/ctf_orchestrator/l2-config.json

# DASCTF 2025（7 题有真值）
python src/ctf_orchestrator/eval_run.py --platform dasctf2025 --config src/ctf_orchestrator/l2-config.json
```

常用参数：

| 参数 | 作用 | 例 |
|---|---|---|
| `--only <cid>` | 只跑指定题（先小规模试） | `--only cry-polly-crack-this` |
| `--difficulty easy,moderate` | 按难度筛 | ctftiny/nyu 有效 |
| `--categories crypto,rev` | 按题型筛 | |
| `--exclude <cid>` | 跳过 | |
| `--max-rounds 4 --max-attempts 3` | 轮次/单题续派预算 | |
| `--workspace <dir>` | 黑板目录（默认 eval-workspace） | |
| `--config <json>` | 模型配置 | 默认 L1（flash 双弱），比赛用 l2-config.json |

成绩单打印在控制台（solved X/Y + 按题型分布），每题 worker 全程日志在
`<workspace>\challenges\<cid>\worker_*.log`。

### 4.2 打开 UI 与互动

```powershell
python src/ctf_orchestrator/dashboard.py --workspace D:/ctf-agent/workspace --port 8088
```

浏览器打开 **http://127.0.0.1:8088/ui/**（旧模板页在 http://127.0.0.1:8088/，两者都可用）。

**列表页**（10s 自动刷新）：

| 列 | 含义 |
|---|---|
| 状态徽标 | 灰=未开始 / 蓝=解题中 / 绿=已解出 / 橙=待提示（等人工或自动续派） |
| 竞速/尝试 | worker 竞速轮次与尝试次数 |
| 耗时 | 各 worker 累计秒数 |
| 成本(¥) | 累计 API 费用（悬停看 token 数） |

**详情页**（点列表任一行进入，15s 刷新）五个区块：

1. **当前摘要（AI 翻译日志）**：3 行中文——正在尝试什么 / 最近结果如何 / 卡点提示。
2. **人工纠偏（hint）**：输入框写提示 → 点"写入提示" → 编排器下一轮派工自动注入。
   写法：一次一个方向、指向具体线索（好："看 PNG 文件尾部的 base64"；废："多想想隐写"）。
3. **方向看板（Supervisor 维护）**：Ideas（待验证方向，带状态）+ Memory（事实/失败边界）。
4. **提交复核**：开关"复核模式"后，worker 的候选 flag 不再自动提交，出现在这里由你点
   "确认提交"（写入 requests/confirm，编排器代交）。
5. **最近工具调用**：worker 实时动作（▶ 调用 / ↳ 结果，错误红显）。

### 4.3 在 UI 里跑 benchmark（端到端）

**核心原则：dashboard 与 eval_run 必须指向同一个 workspace。**

```powershell
# 终端 A：看板（后台常驻）
python src/ctf_orchestrator/dashboard.py --workspace D:/ctf-agent/eval-workspace --port 8088

# 终端 B：跑评测（同一个 workspace）
cd D:\ctf-agent
python src/ctf_orchestrator/eval_run.py --platform ctftiny --only cry-polly-crack-this ^
     --workspace D:/ctf-agent/eval-workspace --config src/ctf_orchestrator/l2-config.json
```

然后浏览器 http://127.0.0.1:8088/ui/：

1. 列表页实时看到题目从"未开始"→"解题中"→"已解出/待提示"；
2. 点进题目看 digest 与工具调用，理解 worker 在干什么；
3. 卡住的题（橙色待提示）写 hint → 下一轮注入生效（eval_run 有 `--max-rounds` 多轮时可见）；
4. 想人工把关：开复核模式，候选 flag 由你确认；
5. 跑完控制台出成绩单；UI 保留全部状态可回看，成本列显示每题花费。

### 4.3b 新方式：UI 内置 Benchmark 模块（推荐）

看板左侧栏新增「Benchmark 跑分」页，**不用开第二个终端**：

1. 起看板（同上终端 A），浏览器开 http://127.0.0.1:8088/ui/ → 左侧栏点「◈ Benchmark 跑分」；
2. 页面上方 4 张题库卡（CTFTiny / NYU / Cybench / DASCTF2025，显示题数/真值数/分类分布）——**点选一个**；
3. 过滤器：难度下拉 + 题型（逗号分隔）+ 只跑指定 cid + 排除 cid；
4. 点「开始跑分」→ 状态面板实时显示：运行中/已完成、耗时、pid、**成绩单实时统计**
   （解出 x/y · 成本）、控制台日志尾部自动刷新；「停止」按钮随时终止；
5. 跑分中/结束后，下方挑战星卡网格与比赛页同款：点进题目看 AI 摘要、工具调用流、
   **写 hint 纠偏**、方向看板、复核提交——全部可用；
6. 每次开跑自动清空上一次成绩（黑板重来，成绩单干净）。

后台实现：dashboard 拉起的 `eval_run.py` 子进程（独立进程组，停止=taskkill /T），
跑分 workspace 固定 `D:/ctf-agent/eval-workspace-bench`（与比赛 workspace 隔离）。

**跑分持久化（重启不丢）**：每次跑分自动归档到 `eval-workspace-bench\runs\<run_id>\`
（黑板/成绩单/控制台日志/每题 worker 日志），索引在 `runs.json`。页面「历史跑分」表
列出全部历史（时间/题库/状态/成绩/耗时/过滤条件），点「查看」进入**只读回看**
（题目列表/digest/全程记录/看板全部可看，hint 与复核不可写）；看板重启后历史仍在，
运行中的跑分也会被自动收养（按 pid 判活）。每次开跑前自动把上一轮产物归档，成绩单干净。

**看板重启不杀跑分 + 断点续跑（2026-08-17）**：

- 重启看板时**只杀看板进程本身**（`taskkill /F /PID`，不要加 `/T`），跑分子进程继续跑；
  看板重启后按 `run.pid` 文件自动收养运行中的跑分（状态/日志照常显示，停止按钮也有效）；
- 跑分中途死掉（断电/误杀）→ 历史表该行出现「**续跑**」按钮：从归档的进度快照
  （`runs/<id>/state.json`）恢复黑板，已解出的题保持 solved，未解的从断点继续，
  不重复花 token。新跑分记录会标记 `resumed_from` 来源。

### 4.5 本地 KB（可选，评测默认关闭）

- 配置 `l2-config.json` 加 `"kb_enabled": true` → 编排器自动拉起 kb_server(:8099) 并给
  worker 打开 kb_search 工具；worker 会按题型检索"手法参考"。
- 也可手工常驻：`python src/ctf_orchestrator/kb_server.py`；测试：浏览器
  `http://127.0.0.1:8099/search?q=RSA`。
- 评测时保持关闭（完整性铁律：公开题解检索会使能力评测失真）。

## 五、常见问题排查

| 症状 | 排查 |
|---|---|
| worker 秒退/无输出 | 看 `<ws>\challenges\<cid>\worker_*.log` 开头；`Unknown option` = 命令构造问题（不应再出现）；检查 Kali SSH |
| Kali 工具报错 | `ssh kali@10.174.153.128` 手动测；确认 secrets/kali.json 正确；Kali API(5000) 崩不影响 SSH 工具（仅影响 preflight/eval 健康闸门） |
| UI 空白/404 | 确认 `ui\dist` 存在（没有则 `cd ui && npm run build`）；访问带 `/ui/` 前缀 |
| 端口被占 | 8088/8089/8099 冲突时看板用 --port 换端口；worker-api/KB 会打印 busy 并降级 |
| 成本看不到 | 列表成本列来自 worker 日志 usage 聚合（mtime 缓存），跑过题的才显示 |
| 想复现某个 bug | 单题 + `--only` + `--max-rounds 1`，worker 日志全在 challenges/<cid>/ |
