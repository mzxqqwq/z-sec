## 一、策略（一句话）

**拉题 → 一强一弱双模型竞速 → Observer 旁路监督纠偏 + 续跑防早停 + 人工 hint 兜底 → 交卷。
中心永远是"把当前这道题解出来"，不换题、不放弃、不杀进程。**

## 二、架构

```
┌─ Windows ───────────────────────────────────────────────────────┐
│ ctf_orchestrator.py（指挥官）                                    │
│   拉题(60s poller) → planning(强模型出总体思路)                   │
│   → 每道题派 1 强 + 1 弱 worker 竞速（并发上限 3 题）              │
│   supervisor.py：Observer 移植（6 轮审查/10 轮窗口/维护看板/提醒）  │
│   ralph-loop：agent_end 未解 → 注入"继续推进"强制续跑              │
│   board：Idea/Memory 双层看板（state.json）                      │
│   submit：直接提交（纪律已删，平台规则回来再加，留开关位）          │
│   conclude（8/19 后）：deadline-90s abort+总结收尾               │
├─ pi worker（node cli.js --mode rpc，已切；8/19 后按计划启用的能力均已上线）   │
│   kali.ts 扩展：                                                │
│     · bash/read/write/edit → SSH（paramiko 等价物 ssh2）→ Kali   │
│     · submit_flag/get_hint → Windows 本地 worker-api(:8089)      │
│     · kb_search（已上线，评测默认关）                             │
├─ UI（React + Vite，新目录 ui/）                                  │
│   · 题目列表/状态/耗时/成本 · digest 3 行中文摘要                  │
│   · 最近工具调用折叠原文 · Idea/Memory 看板 · hint 输入框          │
│   · verify 开关 + 待确认 flag + 确认按钮                          │
│   · Flask 后端（dashboard.py 扩展）供状态/digest/hint/confirm API │
└──────────────────────────────────────────────────────────────────┘
         │ SSH (root，凭据在 secrets/kali.json)                     
         ▼                                                         
┌─ Kali（10.174.153.128，NAT）───────────────────────────────────┐
│ /root/ctf/<cid>/w<idx>/  每 worker 独立工作目录                   │
│ 工具链：pwntools/angr/z3/sympy/fpylll/blutter/stegseek/...        │
│ 已补：SageMath 10.9（podman 容器包装 /usr/local/bin/sage）、      │
│       pwndbg（/opt/pwndbg）、gdb 17.2（2026-08-17 装齐）          │
│ 出网：pip 装包/查资料/连靶机（NAT 天然支持）                       │
└──────────────────────────────────────────────────────────────────┘
```
