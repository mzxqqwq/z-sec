> 配套阅读：`ANALYSIS-ADAPT.md`（14 项改动计划，idea 来源）、`ARCHITECTURE-DETAIL.md`（实现细节）。

## 1. 一句话

**一个 Python 编排器（指挥官）指挥多个 pi 解题员（LLM agent），在 Kali 上干活，向比赛平台交 flag。**

我们自研的只有「指挥官」（调度、状态、纪律、看板）；「解题员」用现成的开源 agent 运行时 pi（腾讯黑客松唯一 AK 战队同款后端）；「工具箱」是 Kali（装好 pwntools/angr/z3/fpylll/blutter 等）；「考场」是 DASCTF 平台 API。

| 部件 | 是什么 | 谁做的 |

## 3. 一次解题的 10 步（跟一遍就懂）

以一道 crypto 题为例，代码路径：

1. **拉题**：`platform.list_challenges()` → 得到 NormalizedChallenge（题名/分类/描述/附件清单），存进黑板
2. **入黑板**：`workspace/state.json` 记录这道题，状态 = new（状态机见 §5）
3. **triage**：按难易排序，easy 先打（3 小时抢分策略的核心）
4. **planning**：planner 用便宜模型生成 3-6 步解题计划（306 字符左右），注入 worker 提示词
5. **派工**：按 `l2-config.json` 路由——crypto/pwn 用 v4-pro+flash 双模型、misc/rev 用 flash×2，起 2 个 worker **竞速**（谁先出 flag 谁赢）
6. **worker 干活**：pi 循环思考→调工具；附件先由编排器同步到 Kali `/root/ctf/<cid>/attachments/`，worker 的 bash 全部经 kali.ts 转发到 Kali 执行
7. **僵局监测**：stuck.py 实时读 worker 的 json 事件日志，重复调用/错误率高/发呆 300s → 杀进程重派（提示词加"换思路"警告）
8. **抽 flag**：worker 输出里用 FLAG_PATTERNS 正则抽候选 flag（黑名单滤掉 flag{path} 等占位符）
9. **提交**：submit.py 纪律——递增冷却 [0,15,60,180]s、精确去重、每题 races 预算——交平台判对错
10. **记成绩**：对 → solved，冲下一题；错/卡 → 重派或 needs_hint（人工写提示）或 dead（放弃保时间）

## 4. 数据都放在哪（比赛时找东西看这里）

| 路径 | 内容 |
|---|---|
| `workspace/state.json` | 黑板：每题状态/竞速次数/提交记录（唯一真相源） |
| `workspace/challenges/<cid>/` | 附件 + worker_*.log（解题全过程 json 事件流） |
| `workspace/hints/<cid>.md` | 人工提示：写文件即注入下一轮 worker 提示词 |
| `workspace/requests/confirm/<cid>.json` | 人工复核：写 {"flag": "..."} 由编排器代交 |
| Kali `/root/ctf/<cid>/` | 远程执行现场（附件、脚本、exp） |
| `eval-workspace/` | 评测专用黑板（与比赛隔离，防污染） |

比赛日 = 真考场（DasctfPlatform）；平时练 = eval_run.py + 本地题库（数据在 Windows，真值不下 Kali）。

| 11 | 结构化输出约束（只收 flag_found） | ❌ | 现在靠正则抽 flag + 黑名单 |
