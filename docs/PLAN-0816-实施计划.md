## 1. 任务清单

### T1 SSH 通道替换 REST ⬜
- **改动**：`src\pi-ext\kali.ts` 重写——bash/readFile/writeFile/edit 从 REST
  （POST :5000/api/command）改为 ssh2 连接（`npm install --prefix src\pi-ext ssh2`）；
  连接复用 + 命令超时 + 断线重连；远程路径映射不变（/root/ctf/<cid>/w<idx>/）。
- **凭据**：新建 `secrets\kali.json`（host/port/username/password，已 gitignore，开源前删）。
- **保留**：Kali REST `/health` 作为健康闸门（eval_run/preflight 不换）。
- **验证**：mock 平台跑一轮双 worker 全链路；worker 日志无连接错误、Kali 上出现
  /root/ctf/<cid>/w0、w1 目录与执行痕迹；`ssh root@10.174.153.128 'echo ok'` 通。

### T2 状态机简化 ⬜
- **改动**：`ctf_orchestrator.py` + `state.py`——删除 triage 排序（easy-first）、races 预算、
  dead 状态、stuck 击杀与重派逻辑；状态流转仅保留 new → solving → solved / needs_hint；
  提交纪律（submit.py 冷却/去重/上限）注释保留为 parked 开关（platform 规则回来再启用）。
- **保留**：3 题并发上限、每 worker 25 分钟超时、deadline 强杀（防孤儿）。
- **验证**：mock 平台 4 题跑通；state.json 状态流转无非法迁移；代码 grep 无 triage/races/dead 残留调用。

### T3 Planner 简化 ⬜
- **改动**：`planning.py`——prompt 改为"阅读题目给出解题总体思路（核心方向 + 2-3 个关键
  注意点），不要列死板的工具步骤"；模型改强模型（v4-pro 对应 id）；删除步骤数门禁与
  失败重规划相关代码。
- **验证**：mock 一题看 plan 输出（应为思路型文本）；`--no-planning` 开关仍可用。

### T4 w<idx> 目录隔离 ⬜
- **改动**：`ctf_orchestrator.py` remote_root 加 `/w<idx>`（每 worker 独立）；`kali.ts`
  的 toRemote 路径映射同步；附件同步到 w0（弱 worker 从 w0 拷贝/独立同步）。
- **验证**：mock 双 worker 同题运行，各自目录内文件互不覆盖。

### T5 ralph-loop 续跑（编排器层 v1） ⬜
- **改动**：worker 完成且未解出 → 自动续派（预算内：每 worker 续派上限 3 次），续派提示词
  追加"继续当前任务，不要重复已完成步骤；多 flag 题交对一个不要停，直到平台显示完成"；
  提示词模板加入该契约（对齐 BreachWeave ralph-loop.ts:7-8 语义）。
- **注**：进程内续跑（agent_end 强制 triggerTurn）依赖 T11 rpc 改造，v1 先做编排器层等价。
- **验证**：benchmark 单题复测，观察未解自动续派与提示词生效。

### T6 Supervisor v1（BreachWeave Observer 移植） ⬜
- **改动**：新建 `supervisor.py`——每 6 轮工具调用（或 hint/agent_end）审查一次；输入最近
  10 轮压缩轨迹（每轮 = assistant 摘要 + 工具名/参数160字/结果160字/is_error）；
  独立会话 + 强模型；系统提示词全文移植 observer-agent.ts:11-179（三步闭环
  先闭环→后收缩→最后扩张、failed 三连自问、send_efficiency_reminder 四前提+冷却+指纹去重、
  NO_CHANGE 契约）；产出 = 看板维护动作（T7）+ 效率提醒（注入下一轮提示词）。
- **验证**：benchmark 单题开/关 Supervisor 对照；日志可见审查触发与看板更新。

### T7 Idea/Memory 看板 ⬜
- **改动**：`state.py` 每 cid 加 `board: {ideas[], memory[]}`（Idea: pending/testing/verified/
  failed/skipped + lowercase 去重；Memory: fact/evidence/failure/hint）；Supervisor 写、
  worker 只读（提示词注入摘要，memory≤12×220字、ideas≤8×120字）。
- **验证**：mock 解题时 board 随 supervisor 审查更新，worker 提示词含摘要。

### T8 submit_flag/get_hint 工具化 ⬜
- **改动**：`kali.ts` 注册 `submit_flag`/`get_hint` 工具 → POST 本地 worker-api（新建
  `worker_api.py`，端口 8089）→ 编排器统一处理（当前直接提交，纪律 parked）；正则抽 flag
  保留为兜底。
- **验证**：mock 端到端：worker 调 submit_flag → 编排器提交 → 判题 correct。

### T9 React UI v1 ⬜
- **改动**：新建 `ui/`（Vite + React + TS）；`dashboard.py` 扩展 API：GET /api/state、
  GET /api/digest/<cid>、POST /api/hints/<cid>、POST /api/confirm/<cid>、GET /api/logs/<cid>；
  新建 `digest.py`（LLM 把 worker 日志尾翻译成 3 行中文摘要：在试什么/上次结果/卡点原因，
  每分钟缓存）；前端页面：题目列表（状态徽标/耗时/成本）、详情（digest/最近工具调用折叠/
  board 看板/hint 输入框/verify 开关+确认按钮）。
- **验证**：浏览器 127.0.0.1:8088 全页面可用；mock 解题时页面实时刷新；**benchmark 全程使用**。

### T10 message bus（文件版） ⬜
