# 系统架构说明：从零理解我们现在的系统

> 配套阅读：`使用手册-完整版.md`（操作与 UI）、`定版方案-最终.md`（最终决策）、
> `服务题容器运行.md`（benchmark 靶机起容器）。
> 本文按「先看整体 → 跟一次解题 → 看数据 → 对照计划查进度」的顺序，适合逐步理解。

---

## 1. 一句话

**一个 Python 编排器（指挥官）指挥多个 pi 解题员（LLM agent），在 Kali 上干活，向比赛平台交 flag。**

我们自研的只有「指挥官」（调度、状态机、看板、监督）；「解题员」用现成的开源 agent 运行时
pi（腾讯黑客松唯一 AK 战队同款后端）+ 自研 kali.ts 扩展；「工具箱」是 Kali
（pwntools/angr/z3/sympy/fpylll/blutter/stegseek/jadx/SageMath/pwndbg…）；
「考场」是 DASCTF 平台 API。

分工一句话版：

| 部件 | 是什么 | 谁做的 |
|---|---|---|
| 编排器 | 指挥：拉题→派工→监督→抽 flag→交卷→续跑 | 自研（Python） |
| pi worker | 解题员：LLM 循环"思考→调工具→看结果" | 开源 pi（MIT）+ 我们的 kali.ts/loop-detect.ts 扩展 |
| Kali | 工具箱：所有命令/脚本/exp 在这里执行 | 现成机器+工具链 |
| 平台适配器 | 考场抽象：拉题/交卷一个接口，换平台只换实现 | 自研（BasePlatform） |
| 看板 | 人机回路：看状态/写提示/复核提交 | 自研（Flask + React） |

## 3. 一次解题的 10 步（跟一遍就懂）

以一道 crypto 题为例，代码路径：

1. **拉题**：`platform.list_challenges()` → NormalizedChallenge（题名/分类/描述/附件清单），存进黑板
2. **入黑板**：`workspace/state.json` 记录这道题，状态 = new（状态机见 §5）
3. **planning**：planner（强模型）出总体思路，注入 worker 提示词
4. **派工**：每题派 1 强（v4-pro）+ 1 弱（v4-flash）双 worker **竞速**（谁先出 flag 谁赢），并发上限 3 题
5. **worker 干活**：pi 循环思考→调工具；附件由编排器同步到 Kali `/root/ctf/<cid>/w<idx>/attachments/`，bash 全部经 kali.ts 走 SSH 在 Kali 执行
6. **监督**：supervisor 每 6 轮审查一次（10 轮窗口）——**起一个独立 pi 观察者会话**（`-e observer.ts`，不加载 kali.ts），模型通过看板工具（board_list/idea_add/idea_update/memory_add/memory_update/memory_delete/send_efficiency_reminder）直接维护 Idea/Memory 看板；编排器只读回 board.json 合并进黑板，不解析模型输出（对齐 BreachWeave 架构，杜绝推理模型空输出事故）；效率提醒带冷却去重，纠偏注入下一轮提示词
7. **抽 flag**：worker 输出里用 FLAG_PATTERNS 正则抽候选 flag（黑名单滤掉占位符）
8. **提交**：worker 可经 submit_flag 工具提交（worker-api 回调），编排器统一直接提交判对错（无冷却纪律——平台规则回来再加，留 parked 开关）
9. **未解续跑**：agent_end 未解 → 注入"继续推进"续跑（ralph-loop 语义，模型无权宣布放弃）；deadline-90s 才 conclude 收尾
10. **记成绩**：对 → solved 冲下一题；错/卡 → 下一轮自动续派，或 needs_hint 等人工提示

## 4. 数据都放在哪（比赛时找东西看这里）

| 路径 | 内容 |
|---|---|
| `workspace/state.json` | 黑板：每题状态/尝试记录/看板（唯一真相源） |
| `workspace/challenges/<cid>/` | 附件 + worker_*.log（解题全过程 json 事件流） |
| `workspace/hints/<cid>.md` | 人工提示：写文件即注入下一轮 worker 提示词 |
| `workspace/requests/confirm/<cid>.json` | 人工复核：写 {"flag": "..."} 由编排器代交 |
| Kali `/root/ctf/<cid>/w<idx>/` | 每 worker 远程执行现场（附件、脚本、exp） |
| `eval-workspace-bench/` | Benchmark 专用黑板（看板 Benchmark 页跑分） |
| `eval-workspace-bench/runs/<id>/` | 每轮跑分归档（黑板/成绩单/日志，可回看、可续跑） |

比赛日 = 真考场（DasctfPlatform）；平时练 = eval_run.py + 本地题库（数据在 Windows，真值不下 Kali）。

## 5. 状态机（定版：无 triage/无僵局击杀/无放弃）

```
new → queued → solving（一强一弱竞速）→ solved
    ↘ needs_hint（人工提示或下一轮自动续派）←── 未解自动续派（预算内）
```

只有五个状态，没有 dead/放弃：**永远把当前题解出来**（AK 导向）。

## 7. 建议的互动走读路线（一步一步来）

1. **第 1 步（推荐先做，5 分钟见全貌）**：起 mock 假考场（7788）+ 看板（8088），跑一次全链路，对着日志认 §3 的每一步
2. 第 2 步：读 `ctf_orchestrator.py` 的 run_round()（状态机怎么转）
3. 第 3 步：读 `workers.py`（怎么派工/解析/组杀）
4. 第 4 步：读 `supervisor.py` + `src\pi-ext\observer.ts` + `message_bus.py`（监督与协作）
5. 第 5 步：看板 + hints + confirm（人机回路四件套）
6. 第 6 步：评测体系（eval_run + bench_admin + 服务题容器运行 + 真值隔离）

每步 10-20 分钟，走完 6 步你对整套系统就"看得见摸得着"了。
